# v0.5.8 Spec

## Goal

격자 한 칸 단위 이동의 논리(snake 배열·격자 판정·충돌)는 그대로 유지하되, 칸과 칸 사이를 선형 보간(tween)하여 뱀의 모션이 한 박자씩 끊겨 보이지 않고 부드럽게 흐르도록 한다. 보간은 **렌더 전용**이며 게임 로직·타이밍·점수·충돌에는 일절 영향을 주지 않는다.

## User Stories

- 플레이어로서, 뱀이 칸에서 칸으로 순간이동하듯 끊겨 보이지 않고 부드럽게 미끄러지듯 이동하기를 원한다. 그래서 느린 튜토리얼·초반 스테이지에서도 모션이 뚝뚝 끊기지 않아 보기에 쾌적하다.
- 플레이어로서, 모션이 부드러워지더라도 게임의 속도감·조작감·충돌 타이밍은 이전과 똑같기를 원한다. 그래서 부드러워진 화면 때문에 난이도나 반응성이 달라졌다고 느끼지 않는다.
- 플레이어로서, 일시정지·카운트다운·오버레이·BLOCKED 등 게임이 멈춰 있는 상태에서는 뱀이 어색하게 떠다니거나 미끄러지지 않기를 원한다. 그래서 정지 상태가 명확하게 "멈춰 있다"고 느껴진다.

## Acceptance Criteria

### Set A — 렌더 진행도 t 산출

- [ ] 렌더 진행도 `t`를 `tickAccum / stage.tick`로 계산하고 `[0, 1]`로 clamp한다 (`t = Math.min(1, Math.max(0, tickAccum / stage.tick))`).
- [ ] `t`는 `frame(now)` 루프 내 `draw(now)` 호출 시점에 사용 가능한 값이어야 한다. 단, `frame()`의 `while (tickAccum >= stage.tick)` 소비 루프가 끝난 **이후**의 `tickAccum` 잔여값을 기준으로 한다 (한 프레임에 여러 tick이 소비될 때 잔여분만 보간에 쓰여 점프가 발생하지 않는다).
- [ ] `state === STATE.PLAYING`이 아닌 모든 상태에서 `t`는 보간을 발생시키지 않는 값으로 고정된다 (Set C 참조). PLAYING이 아닐 때 `tickAccum`이 0이라는 보장에 의존하지 말고, 렌더 경로에서 명시적으로 보간을 끈다.
- [ ] `t` 산출은 새 `setInterval`/`setTimeout` 없이 기존 RAF(`requestAnimationFrame(frame)`) 루프 내에서만 이루어진다.

### Set B — 세그먼트 이전 위치(prevSnake) 캡처

- [ ] 각 세그먼트 `i`의 "직전 격자 위치"를 보관하는 렌더 전용 스냅샷(예: `prevSnake`)을 둔다. 이는 `snake` 논리 배열과 **별개의 배열**이며 논리 배열을 변형하지 않는다.
- [ ] `prevSnake`는 `tick()`이 `snake`를 변경(`unshift`/`pop`)하기 **직전**의 좌표를 담는다. 즉 매 논리 tick 직전에 현재 `snake`를 좌표 복사(`{x, y}` 단위의 깊은 복사)하여 `prevSnake`로 저장한다.
- [ ] 보간된 렌더 위치 = 각 세그먼트에 대해 `lerp(prevPos, currPos, t)`. `lerp(a, b, t) = a + (b - a) * t`. 셀 좌표 단위로 lerp한 뒤 픽셀로 변환하거나, 픽셀 단위로 lerp하거나 결과가 동일하면 무방하다.
- [ ] 머리(index 0)는 **다음 칸(현재 `dir`/`nextDir` 진행 방향)으로 진입하는 보간**으로 표현된다. 즉 머리의 렌더 위치는 직전 머리 칸 → 현재 머리 칸 사이를 `t`로 보간한 값이다. (`tick()`에서 `dir = nextDir`가 이미 반영된 현재 `snake[0]`가 목표 칸이고, `prevSnake[0]`가 출발 칸이다.)
- [ ] 머리보다 뒤 세그먼트 `i`(>=1)는 각자 `prevSnake[i] → snake[i]`를 `t`로 보간한다. 결과적으로 각 세그먼트가 "한 칸 전 자기 자리 → 현재 자리"로 미끄러진다.

### Set C — cellCenter 단일 진입점에 보간 주입

- [ ] 보간 오프셋은 `cellCenterX(seg)` / `cellCenterY(seg)`(현 421–429행) 또는 그 호출 경로에 주입한다. 이 두 함수가 body·bulge·head·corner 경로 전부의 단일 좌표 진입점이므로, 여기에 보간을 넣으면 `drawSnakeBody`(617–679행), `drawBulges`, `drawSnakeHead`(681–731행)가 모두 자동으로 보간된 좌표를 사용한다.
- [ ] 보간 주입 후에도 `drawSnakeBody`의 코너 판정(`isCorner`)과 `quadraticCurveTo` 경로 구조(658–665행)는 **격자 좌표 기준 그대로** 동작한다. 즉 코너 여부·곡선 제어점 선택 로직은 논리 격자 좌표(`snake[i].x/y`)로 판정하고, 화면에 그릴 점만 보간된 좌표를 쓴다. 코너 경로가 보간 때문에 깨지거나 펄럭이지 않는다.
- [ ] `drawSnakeHead`의 `ctx.translate(cx, cy)` 기준점이 보간된 머리 좌표가 되어 머리가 부드럽게 따라온다. 단, 머리 회전(`ctx.rotate(angleFromDir(direction))`)은 **보간하지 않는다**(회전 애니메이션은 Non-goal). 머리 방향은 현재 `dir` 기준 즉시 전환을 유지한다.
- [ ] `midX`/`midY`(626–627행)가 보간된 `cellCenterX/Y`를 경유하므로 캡슐 스트로크의 시작·중간점도 자동으로 보간된다. 머리–몸통 연결 지점(637행)이 보간 후에도 연속적이다.

### Set D — 꼬리/성장 tick 처리

- [ ] 일반(성장 없는) tick에서 꼬리(마지막 세그먼트)는 `prevSnake[len-1] → snake[len-1]`로 보간되어 한 칸 전 자리에서 현재 자리로 자연스럽게 따라온다.
- [ ] 성장(사과 섭취) tick에서는 `snake`가 `pop` 없이 `unshift`만 되어 길이가 +1 된다. 이때 `prevSnake`(직전 프레임, 더 짧은 배열)와 `snake`(현 프레임, 더 긴 배열)의 길이가 다르다. 새로 생긴 꼬리 세그먼트가 첫 보간 프레임에서 어색하게 튀거나 깜빡이지 않도록 처리한다 — 새 꼬리는 직전 위치가 자기 자신(정지)이거나 직전 꼬리 위치에서 보간되어 "꼬리가 한 박자 늦게 따라오는" 효과로 보여야 한다.
- [ ] 인덱스 정렬 규칙을 명시한다: 성장 tick에서 머리가 index 0으로 들어오며 기존 모든 세그먼트의 절대 위치는 그대로다(꼬리만 안 빠짐). 보간 시 `prevSnake[i]`와 `snake[i]`를 같은 절대 세그먼트가 아닌 같은 인덱스로 매칭하면 한 칸씩 어긋날 수 있으므로, 성장 프레임에서의 인덱스 오프셋(머리 추가로 인한 +1 시프트)을 보정한다. (참고: 기존 bulge progress도 동일 사유로 `tick()` 399–402행에서 +1 시프트한다.)
- [ ] 보간 도중 `snake.length` 또는 `prevSnake.length` 불일치로 인한 배열 인덱스 초과 접근(undefined 좌표 → NaN)이 발생하지 않는다. 길이 불일치 프레임에서도 안전하게 폴백한다(보간 없이 현재 좌표 사용 등).

### Set E — 정지/전이 상태 엣지케이스 (보간 미적용/고정)

- [ ] `STATE.PAUSED`: 뱀이 미끄러지지 않고 마지막 격자 위치에 고정된다(`t` 보간 미적용). 재개 시 부드럽게 이어진다.
- [ ] `STATE.READY`: 시작 전 뱀이 정지 상태로 보인다(보간 미적용).
- [ ] `STATE.COUNTDOWN`: 카운트다운 3·2·1 동안 뱀이 미끄러지지 않는다(보간 미적용). `tickAccum`이 0으로 리셋되는 `finishCountdown()`(373행) 이후 PLAYING 진입 시점부터 보간이 시작된다.
- [ ] `STATE.STAGE_CLEAR`: 클리어 홀드(800ms) 동안 뱀이 미끄러지지 않는다(보간 미적용).
- [ ] `STATE.OVER`: 게임오버 정지 화면에서 뱀이 미끄러지지 않는다(보간 미적용).
- [ ] `STATE.BLOCKED`(튜토리얼 noFailOnHit): 벽 앞에서 멈춘 상태이므로 뱀이 벽 쪽으로 계속 미끄러져 들어가거나 떠다니지 않는다(보간 미적용 또는 `t`를 0으로 고정). BLOCKED 해제(`tryUnblock` 성공, 919행에서 `tickAccum = 0`) 후 PLAYING부터 보간 재개.
- [ ] `STATE.CHOICE`/`STATE.HELP`: 해당 오버레이가 떠 있는 동안 캔버스 보간이 어색하게 흐르지 않는다.
- [ ] 위 모든 정지 상태에서 PLAYING으로 (재)진입할 때 보간이 끊김 없이 자연스럽게 시작된다. 특히 `tickAccum = 0`으로 리셋되는 진입 경로들(`finishCountdown` 373행, `tryUnblock` 919행, resume 경로)에서 첫 프레임 `t≈0`으로 출발한다.

### Set F — 회귀 (변경 없음 확인)

- [ ] `STAGES` 배열의 tick 값이 불변이다: 튜토리얼 `420`, 스테이지1 `220`, 스테이지2 `180`, 스테이지3 `150`(현 112–115행). 논리 이동 속도가 변하지 않는다.
- [ ] `tick()` 함수의 충돌 판정 타이밍(`wouldHit` → `gameOver`/`enterBlocked`, 382–385행)이 불변이다. 보간은 충돌이 이미 격자 단위로 확정된 **이후**의 화면 표현일 뿐이며, 충돌 시점을 앞당기거나 늦추지 않는다.
- [ ] `snake` 논리 배열, `food`, `score`, `applesEaten`, `bulges`(progress/spawnLen 인덱스 포함)는 보간 로직에 의해 변경되지 않는다.
- [ ] 스테이지 전환(`enterStageClear` → `advanceStage`), 점수 누적, 사과 배치(`placeFood`) 동작이 v0.5.7.2와 동일하다.
- [ ] 모바일(터치 회전·캔버스 폴백·하단 버튼) 및 키보드 조작 반응이 v0.5.7.2와 동일하다. 입력은 여전히 다음 논리 tick에 반영된다(보간은 입력 큐잉/반영 타이밍을 바꾸지 않는다).
- [ ] eat squash·pulse(`computeSquash`/`computePulse`)와 사과 wobble 등 기존 ambient/소화 모션은 본 버전에서 손대지 않는다(v0.5.9 범위).
- [ ] UI 스케일링·HiDPI(`cellSize = canvas.width / cols`) 동작이 불변이며, 보간 좌표도 동일한 `getStageOffset()`/`cellSize` 기준으로 계산된다.

- 머리 회전 애니메이션(방향 전환 시 부드러운 회전 보간). 머리 방향은 즉시 전환 유지.
- 논리 tick 구조 변경(`frame()`의 `while (tickAccum >= stage.tick)` 소비 루프, tick 간격, 입력 반영 타이밍).
- 소화 wiggle·bulge 모션, ambient wobble/breathing 등 시각 모션 추가·조정 (v0.5.9 범위).

- 새 외부 라이브러리·빌드툴 도입.
- 코너 Bezier 곡선화 등 기존 backlog.

## Non-functional Notes

### 페이로드 예산

- 전체 목표: 50KB 미만 유지. **현재 합계 약 49.3KB** (game.js 33,932B + index.html 4,251B + style.css 11,121B = 49,304B)로 상한에 매우 근접해 있음. 본 버전은 추가 여유가 거의 없으므로 최소 변경으로 구현해야 한다.
- 보간 로직 추가는 거의 game.js에만 발생하며, prevSnake 캡처 + lerp 헬퍼 + cellCenter 보간 주입 + 상태 게이팅으로 예상 순증가 < 0.7KB.
- 순증가가 50KB 상한을 넘길 위험이 있으면, 동일 효과를 유지하는 범위에서 기존 코드(주석 포함) 정리로 상쇄한다. 빌드툴/미니파이 도입은 금지(정적 3파일 유지).
- 최종 합계가 50KB 미만임을 SCM/QA 단계에서 바이트 단위로 확인한다.

### 성능

- 보간은 기존 RAF(`frame`) 루프 내 산술 연산(세그먼트당 lerp 2회 + 상태 분기 1회)만 추가한다. 새 타이머·새 드로우콜·추가 캔버스 패스 없음.
- 세그먼트 수(최대 20×20 격자 내 뱀 길이)만큼의 O(n) 보간이며, 이미 매 프레임 도는 `drawSnakeBody` 루프와 동일 차수라 체감 비용 무시 가능.
- `prevSnake` 스냅샷은 매 논리 tick당 1회 좌표 복사(O(n))이며 매 프레임이 아니라 tick당 발생하므로 비용이 작다.

### 정확성/논리 불변

- 보간은 화면 좌표 산출에만 관여하고, 충돌·점수·food·bulge 인덱스·상태 전이는 격자 단위 그대로 유지된다(Set F).
- 충돌은 `tick()`에서 격자 단위로 이미 확정되며, 보간된 머리가 화면상 벽/몸통에 "닿아 보이는" 순간과 실제 게임오버 판정 순간이 다를 수 있으나 이는 의도된 동작이다(판정은 격자 진입 시점 고정). 정지 상태 보간 미적용으로 게임오버/BLOCKED 직후 뱀이 벽을 파고드는 표현은 발생하지 않는다.

### 모바일

- 보간으로 인한 추가 입력 지연 없음. 입력은 종전대로 다음 tick에 반영.
- 저성능 단말에서 프레임이 드물게 떨어져도 `t` clamp([0,1])로 인해 뱀이 목표 칸을 넘어 튀지 않는다(오버슈트 방지).

## Decisions

- **(A) 선형 lerp 채택, 이징 미도입** — 격자 한 칸 이동은 거리가 짧고 등속이라 선형 보간만으로 충분히 부드럽다. 이징 곡선은 페이로드·복잡도를 늘리면서 이 스케일에서 체감 차이가 작다. 가변 속도·이징은 본 버전의 Non-goal로 명시.
- **(B) cellCenterX/Y 단일 진입점에 보간 주입** — body·bulge·head·corner 모든 렌더 경로가 `cellCenterX/Y`(421–429행)를 거치므로, 여기 한 곳에 보간을 넣으면 전 경로가 자동 수혜한다. 호출부를 흩어 고치지 않아 변경 범위·페이로드·회귀 위험을 최소화한다.
- **(C) PLAYING 외 전 상태에서 보간 미적용** — 일시정지/카운트다운/스테이지클리어/게임오버/BLOCKED/CHOICE/HELP에서 뱀이 미끄러지면 "멈춤"의 의미가 흐려지고, 특히 BLOCKED·OVER에서 벽을 파고드는 어색한 표현이 생긴다. PLAYING일 때만 보간하고 그 외엔 격자 위치에 고정한다. `tickAccum=0` 보장에 의존하지 않고 렌더 경로에서 명시적으로 게이팅한다.
- **(D) 머리 회전 보간 미적용** — 머리 위치는 보간하되 방향(`angleFromDir`)은 즉시 전환을 유지한다. 회전 애니메이션은 Non-goal이며, 위치 보간만으로 끊김 해소 목표를 달성한다. 방향 보간은 코너 경로 처리와 상호작용이 복잡해 회귀 위험이 크다.
- **(E) prevSnake는 논리 배열과 분리된 렌더 전용 스냅샷** — `snake` 논리 배열을 절대 변형하지 않기 위해 별도 좌표 스냅샷을 둔다. 매 논리 tick 직전에 캡처하여, 보간이 항상 "직전 격자 → 현재 격자" 사이에서만 일어나도록 한다. 성장 tick의 인덱스 시프트는 기존 bulge 시프트 관례(399–402행)와 동일하게 보정한다.
