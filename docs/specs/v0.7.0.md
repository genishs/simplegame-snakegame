# v0.7.0 — 스테이지 난이도 곡선 재설계 (Android versionCode 70001)

**Type:** Rules (게임 규칙 변경)
**Date:** 2026-11-01
**Milestone:** 0.7.0 (vc70001)
**Status:** 소유자 확인 완료(2026-11-01). 초안의 선택지 중 확정된 값으로 고쳤다.

소유자 요청(#50):

1. 스테이지를 깰 때 빨라지는 폭이 필요한 과일 수 증가보다 커서 어렵다. 속도는 **아주 조금씩만** 빨라지게.
2. **1~10 스테이지**는 클리어에 필요한 과일 수가 점점 늘어나게.

4. 시작 메뉴에 **「11 스테이지부터 시작」** 추가.

## 2. 새 표 (확정)

- **tick은 스테이지마다 1%씩만 줄인다**(소유자: 「거의 안 빨라지게, 플레이가 쌓이면 다시 생각」). `tick = round(220 × 0.99^(n−1))`. 감소율은 `game.js`의 상수 `STAGE_TICK_STEP`(0.99) 하나라 나중에 바꾸기 쉽다. 11~13도 같은 곡선을 이어 간다(판이 작다고 따로 빠르거나 느리게 하지 않는다). 1 → 13 전체가 −11%(속도 1.13배)다.
- **필요 과일 수가 속도보다 훨씬 빨리 는다.** 5 → 20개(4배). 1~4는 1개씩, 5부터 2개씩.

## 3. 11~13 — 판 채우기

### 왜 판을 줄였나

뱀은 스테이지마다 길이 3으로 다시 시작하므로, 판을 채우려면 `칸 수 − 3`개를 먹어야 한다. 20×20이면 397개다. 그래서 판을 6×6 → 8×8 → 10×10으로 줄였다(초안의 선택지 A). 칸 수가 홀수인 판(7×7 등)에는 모든 칸을 한 번씩 돌아 제자리로 오는 고리가 없어 끝까지 안전하게 도는 방법이 없으므로, 짝수 칸 판만 쓴다. 판이 작아지면 칸이 커 보인다(튜토리얼 5×5와 같은 방식).

시험에서 모든 칸을 한 번씩 도는 고리를 그대로 따라가게 하면(가장 안전하지만 느린 방법) 게임 시간으로 11 약 1분, 12 약 3분, 13 약 8분이 걸렸다. 11부터 시작해 끝까지 약 12분, 점수 1,910점이다.

### 규칙

- **클리어 판정**: 과일을 먹어 뱀 길이가 `cols × rows`가 되는 순간 클리어. 과일 개수 판정과 같은 자리(먹은 직후, 새 과일을 놓기 전)에서 한다.
- **모든 스테이지 클리어**: 13을 채우면 「모든 스테이지 클리어!」를 띄우고 게임 끝과 똑같이 점수를 최고점에 기록한다(실패 진동은 울리지 않는다). 다시 시작(스페이스·탭·시작 버튼)하면 시작 메뉴로 간다. 0.6.5의 엔드리스(마지막 스테이지에서 끝없이 이어짐)는 없어진다.
- **과일 놓을 칸**: 동시 과일이 1개라 판이 꽉 차기 전에는 빈칸이 늘 있다(마지막 빈칸에 과일이 놓인다). 꽉 차는 순간은 클리어라 과일을 놓지 않는다. 빈칸 목록 방식(`emptyCells`)은 빈칸이 없으면 아무것도 놓지 않는다.
- **꼬리 끝**: 자라지 않는 틱에는 머리가 막 비워질 꼬리 칸으로 들어갈 수 있다(그대로). 막바지에 꼬리를 따라 도는 플레이가 된다.
- **남은 칸 표시**: 판 채우기 스테이지에서만 HUD에 「남은 칸: n」(`칸 수 − 뱀 길이`)이 붙는다. 과일을 먹을 때마다 줄고, 다 채우면 0이다. HUD가 한 줄에 안 들어가는 좁은 화면(폭 390px 이하)에서는 두 줄로 접히고, 0.6.5의 장치(`--hud-extra`)로 그만큼 보드가 줄어 페이지는 스크롤되지 않는다.

## 4. 시작 메뉴

- 「튜토리얼부터 시작」(키 1) / 「바로 게임 시작」(키 2, 스테이지 1) / **「11 스테이지부터 시작」(키 3)**. 처음부터 늘 보인다.
- ← → 는 세 버튼 사이를 한 칸씩 옮긴다(양 끝에서 멈춤). 스페이스는 강조된 버튼을 고른다.
- 세로 화면은 버튼이 세로로 쌓이고, 데스크톱은 두 줄(2 + 1)로 놓인다.
- 11부터 시작하면 점수 0, 길이 3, 6×6 판에서 카운트다운 뒤 시작한다. 처음부터 시작한 판과 같은 최고점을 쓴다.

## 5. 영향

- **점수·최고점**: 과일 하나 10점 그대로. 최고점 저장 키·방식(웹 `localStorage`, 앱은 0.6.5의 셸 저장)은 그대로이고 초기화하지 않는다. 곡선이 바뀌어 예전 최고점과 직접 비교하기는 어렵다.
- **문구**: 도움말의 클리어 규칙 설명과 키 안내(1 / 2 / 3)를 바꿨다.
- **안드로이드 셸**: 바꿀 것 없다. 웹 3파일이 빌드 때 assets로 복사된다. 매니페스트·권한·브릿지 그대로.
- **바뀌지 않는 것**: 충돌·성장·과일 먹기·이동 과일 움직임·입력·일시정지·카운트다운·렌더링. 스테이지 표만 0.6.5로 되돌린 빌드가 같은 입력에서 0.6.5와 프레임마다 같은 상태를 낸다.
