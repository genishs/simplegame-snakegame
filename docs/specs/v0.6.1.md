# v0.6.1 — 이동 과일 먹기 버그 수정 (pass-through eat fix)

**Type:** Bugfix
**Date:** 2026-06-05

## 문제

이동 과일(`fruitMoves` 스테이지)이 **때때로 먹히지 않는** 현상.

머리는 매 `tick`마다 1칸 이동하고, 과일은 별도 누적기(`fruitMoveMs = stage.tick * 4`)로 머리보다 4배 느리게 1칸씩 드리프트한다. 먹기 판정은 `tick()`에서 **머리의 새 칸 == 과일 칸**일 때만 일어난다(`game.js`). 그런데 머리와 과일이 같은 축에서 서로를 향해 한 칸씩 이동하면 **칸을 맞교환(swap)** 한다 — 머리는 과일이 있던 칸으로, 과일은 머리가 있던 칸으로. 둘은 어떤 tick 경계에서도 같은 칸을 공유하지 않고 **서로 통과**해버린다. 한 번 통과한 과일은 머리 뒤로 빠지고, 머리가 더 빠르므로 느린 과일이 영영 따라잡지 못해 **먹을 수 없는 상태**가 된다.

### 재현 (머리 우측 이동)

1. 머리 (5,5), 과일 (6,5)이 머리 쪽(좌)으로 드리프트
2. `moveFruits` 먼저 발화: 과일 (6,5) → (5,5)
3. `tick` 발화: 머리 (5,5) → (6,5)
4. 결과: 머리 (6,5), 과일 (5,5) — 한 번도 안 겹침. 과일이 머리 뒤로 이탈

## 수정

`tick()`에서 머리가 **방금 떠난 칸(prevHead)** 에 과일이 있으면 먹은 것으로 처리한다. swap이나 측면 진입으로 과일이 이번 tick에 머리의 경로와 만난 경우를 포착한다.

```js
const prevHead = snake[0];                 // 곧 비워질 머리 칸
const head = { x: prevHead.x + dir.x, y: prevHead.y + dir.y };
...
let eatIdx = foods.findIndex((f) => f.x === head.x && f.y === head.y);
if (eatIdx === -1) {
  // pass-through eat: swap/측면 진입으로 머리 직전 칸에 닿은 과일
  eatIdx = foods.findIndex((f) => f.x === prevHead.x && f.y === prevHead.y);
}
```

`eatIdx`를 `const` → `let`으로 바꾸고, 1차 판정 실패 시에만 2차 판정. **tick당 최대 1개** 불변 유지(머리 칸 우선, 없을 때만 직전 칸).

## 불변식 / 안전성

- **먹기 = tick() 단일 경로 유지** (planner 위험 #3). 과일 드리프트는 여전히 위치만 바꾸고 먹기/성장/점수를 처리하지 않는다. v0.5.8 prevSnake 렌더 보간 불변식 보존.
- **비-이동 스테이지 무해**: `spawnFood`가 점유 칸(몸통)에 과일을 놓지 않으므로 정지 과일이 prevHead(=직전 머리 칸, 이제 목 segment)에 있을 수 없다. 2차 판정은 절대 매치하지 않음.
- **tick당 1개 불변**: 머리 칸에 과일이 있으면 그것만, 없을 때만 직전 칸을 본다. 두 칸 모두 과일이어도 1개만 먹는다.

## 검증

노드 시뮬레이션으로 swap 마이크로스텝 재현:

- 수정 전: swap → `eaten = 0` (과일이 머리 뒤로 이탈)
- 수정 후: `prevHead == 과일` → `eaten = 1`

## 범위 밖 (보류)

- St3 `fruitMoves:true` 잠정 테스트 플래그는 **유지**. 수정된 버전을 라이브에서 재체감한 뒤 정식화(St7-only) 여부를 별도 결정한다.
- 이동 과일 속도(`fruitMoveMs = stage.tick * 4`) 튜닝은 재테스트 후 판단.
