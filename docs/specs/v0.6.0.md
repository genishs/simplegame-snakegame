# v0.6.0 Spec

## Goal

게임에 **다중 과일**(한 보드에 동시에 여러 과일)과 **이동 과일**(머리를 향해 느리게 드리프트하는 과일)을 도입하고, 스테이지를 **St4~7로 확장**한다. 이를 위해 단일 `food` 객체를 `foods` 배열로 리팩터하고, 스테이지 데이터에 신규 필드 `spawnCount`(동시 스폰 수)·`fruitMoves`(이동 과일 플래그)를 추가한다. 충돌·점수·성장·bulge의 **격자 단위 로직 의미는 유지**하되, 과일 차원만 단수에서 복수로 일반화한다. v0.5.8 렌더 보간과 v0.5.9 ambient/wiggle 모션은 **회귀 없이 불변**으로 유지한다.

> 비고: 원래 로드맵의 v0.6 "풀보드 클리어(full-board clear)" 메커닉은 **본 버전 범위에서 보류**한다(Decisions (F)). v0.6.0은 다중·이동 과일 + 스테이지 확장으로 재정의된다.

## User Stories

- 플레이어로서, 후반 스테이지에서 보드에 과일이 여러 개 동시에 떠 있기를 원한다. 그래서 어느 과일을 먼저 먹을지 동선을 계획하는 재미가 생긴다.
- 플레이어로서, 일부 스테이지에서 과일이 가만히 있지 않고 내 머리 쪽으로 천천히 다가오기를 원한다. 그래서 정적인 사냥이 아니라 살아 움직이는 먹이를 쫓고/유인하는 긴장감이 생긴다.
- 플레이어로서, 이동 과일이 내 몸통을 통과해 지나가더라도 게임이 깨지거나 억울하게 죽지 않기를 원한다. 그래서 이동 과일이 몸통 위를 지날 때 충돌 사고가 나지 않는다.
- 플레이어로서, 스테이지 1~3은 지금처럼 단순(과일 1개·고정)하게 유지되어 학습 곡선이 완만하기를 원한다. 그래서 새 메커닉이 초반부터 한꺼번에 쏟아지지 않는다.
- 플레이어로서, 마지막 스테이지(St7)에서 클리어 없이 계속 이어지는 엔드리스 플레이를 원한다. 그래서 끝까지 도달한 뒤에도 다중·이동 과일로 무한히 도전할 수 있다.

## Acceptance Criteria

### Set A — STAGES 데이터 확장 (spawnCount / fruitMoves / St3 유한화 / St4~7 추가)

- [ ] `STAGES` 배열이 아래 표대로 정의된다. 모든 행에 `spawnCount`·`fruitMoves` 필드가 존재한다(누락 없이 명시 권장).

| idx | id | label | cols×rows | tick | snakeLen | clearAfterApples | spawnCount | fruitMoves | noFailOnHit |
|---|---|---|---|---|---|---|---|---|---|
| 0 | `tutorial` | 튜토리얼 | 5×5 | **420** | 2 | 3 | 1 | false | true |
| 1 | `1` | 스테이지 1 | 20×20 | 220 | 3 | 5 | 1 | false | false |
| 2 | `2` | 스테이지 2 | 20×20 | 180 | 3 | 5 | 1 | false | false |
| 3 | `3` | 스테이지 3 | 20×20 | 150 | 3 | **5**(신규 유한화, was `null`) | 1 | **true**(테스트) | false |
| 4 | `4` | 스테이지 4 | 20×20 | 140 | 3 | 6 | **5** | false | false |
| 5 | `5` | 스테이지 5 | 20×20 | 130 | 3 | 8 | **10** | false | false |
| 6 | `6` | 스테이지 6 | 20×20 | 120 | 3 | 10 | **10** | false | false |
| 7 | `7` | 스테이지 7 | 20×20 | 120 | 3 | **null**(엔드리스) | **10** | **true**(정식) | false |

- [ ] 튜토리얼 `tick`은 **420** 불변이다(memory: feedback_tutorial_non_punishing tick ≥ 320ms 준수).
- [ ] St1·St2의 데이터(tick/clearAfterApples/spawnCount=1/fruitMoves=false)는 현행과 동일하다(회귀 없음).
- [ ] **St3 유한화**: `clearAfterApples`가 기존 `null`(엔드리스) → `5`로 변경된다. 사과 5개를 누적해 먹으면 St3가 클리어되고 St4로 전환된다. 즉 기존 "St3 = 엔드리스 종착역" 동작이 사라진다.
- [ ] **엔드리스 종착역 이전**: 엔드리스(`clearAfterApples === null`)는 이제 **St7에만** 존재한다. St7에서는 사과를 아무리 먹어도 `enterStageClear()`가 호출되지 않고 PLAYING이 계속된다.
- [ ] **기본값 처리**: 코드가 `spawnCount`·`fruitMoves`를 읽을 때, 해당 필드가 정의되지 않은 스테이지라도 안전하게 동작하도록 기본값을 적용한다 — `spawnCount`는 `?? 1`(또는 `|| 1`로 0/falsy 방지 고려), `fruitMoves`는 `?? false`. 위 표는 전 스테이지에 필드를 명시하지만, 향후 스테이지 추가/누락 시에도 단일 과일·고정 과일로 폴백한다.

### Set B — food → foods 배열 리팩터

- [ ] 단일 `food` 객체에 대한 모든 참조가 `foods` 배열(요소: `{ x, y }`, 이동 과일의 경우 추가 보간/타이밍 필드 허용)로 일반화된다. 대상 참조:
  - 선언: `let ... food ...`(166행 부근) → `foods`(배열) 선언.
  - 배치: `placeFood()`(242–253행)가 `spawnCount`만큼 빈 칸에 과일을 채운다(Set C).
  - 충돌/먹기: `head.x === food.x && head.y === food.y`(419행) → `foods`를 순회해 머리와 같은 칸의 과일을 찾는다(Set D).
  - 렌더: `drawApple(food.x, food.y, now)`(942행) → `foods` 각 요소에 대해 `drawApple` 호출(Set F).
- [ ] `init()`/`loadStage()`/스테이지 전환 시 `foods`가 깨끗이 초기화된 뒤 새 스테이지의 `spawnCount`에 맞게 다시 채워진다.
- [ ] `foods`는 모듈 스코프에서 일관되게 관리되며(예: `let foods = []`), `bulges`처럼 배열 재할당이 아닌 내용 갱신 또는 일관된 재할당 패턴 중 하나로 통일한다. 어느 방식이든 스테이지 전환 후 잔여 과일이 남지 않는다.

### Set C — placeFood: spawnCount 충족 + respawn(보드 유지)

- [ ] `placeFood()`(또는 신규 헬퍼)는 현재 `foods`를 비운 뒤, 보드에서 **뱀 몸통과 기존 과일 모두와 겹치지 않는 빈 칸**을 골라 `spawnCount`개의 과일을 채운다.
- [ ] 각 과일은 서로 다른 칸에 놓인다(스폰 시점에는 두 과일이 같은 칸에 겹치지 않는다).
- [ ] **respawn(보드 유지)**: 과일 하나를 먹으면 즉시 빈 칸에 새 과일 1개를 스폰하여 보드의 과일 수가 항상 `spawnCount`개로 유지된다. 엔드리스(St7)·유한 스테이지 공통.
  - 단, 클리어 전환이 발생하는 먹기(누적이 `clearAfterApples`에 도달)에서는 스테이지가 즉시 클리어로 전환되므로 respawn은 의미가 없다 — 클리어 분기에서는 respawn을 건너뛴다(기존 `enterStageClear()` early-return 흐름 유지).
- [ ] **빈 칸 부족 안전처리**: 보드가 거의 가득 차 `spawnCount`개를 모두 놓을 빈 칸이 없으면, 무한 루프에 빠지지 않고 **놓을 수 있는 만큼만** 스폰하고 나머지는 스킵한다. 빈 칸이 0이면 스폰을 0개로 안전하게 마친다(크래시·행 없음).
  - 구현 주의: 현재 `placeFood`의 `while(true)` 랜덤-리트라이 방식은 보드가 가득 찰수록 비효율/무한루프 위험이 커진다. spawnCount=10, 20×20 보드(빈 칸 풍부)에서는 무해하나, 안전 상한(시도 횟수 제한) 또는 빈 칸 목록 기반 선택으로 보호한다(dev 재량).

### Set D — 먹기 / 점수 / bulge / 성장 (다중 과일)

- [ ] 매 tick에서 머리(`head`)가 `foods` 중 **어떤 과일과 같은 칸**이면 그 과일을 먹는다(여러 과일과 동시에 같은 칸이 될 수는 없으나, 첫 일치 과일 1개를 먹는 것으로 정의).
- [ ] 먹은 과일은 `foods`에서 제거된다.
- [ ] 먹기 시 효과는 단수 시절과 동일하다: `score += 10`, `applesEaten += 1`, `updateHud()`, `eatStart`/`tongueFlickAt` 설정, **성장**(`snake.unshift(head)` 후 `pop` 생략), bulge 1개 spawn.
- [ ] **bulge 인덱스 시프트 유지**: 먹는 tick에서 기존 모든 bulge의 `progress += 1`·`spawnLen += 1` 시프트(431–434행)와 `spawnBulge()`(435행) 호출이 그대로 동작한다. 다중 과일이 되어도 한 tick에 최대 1개만 먹으므로 시프트는 +1 단위로 유지된다.
- [ ] **클리어 판정은 누적 먹은 수 기준 유지**: `stage.clearAfterApples != null && applesEaten >= stage.clearAfterApples`이면 `enterStageClear()`(436–438행 의미 유지). 다중 과일이어도 판정 기준은 보드 위 과일 수가 아니라 **누적 `applesEaten`**이다.
- [ ] 먹지 않은 tick에서는 `snake.pop()`(꼬리 제거)로 길이 유지(441행 의미 유지).

### Set E — 이동 과일 (fruitMoves: true 스테이지)

- [ ] `fruitMoves === true`인 스테이지(St3 테스트, St7 정식)에서 각 과일이 **머리를 향해 느리게 한 칸씩 드리프트**한다. `fruitMoves !== true`인 스테이지의 과일은 고정(현행 동작).
- [ ] **PLAYING에서만 이동**: `state === STATE.PLAYING`일 때만 과일이 이동한다. READY/COUNTDOWN/PAUSED/STAGE_CLEAR/OVER/BLOCKED/CHOICE/HELP 등 정지·전이 상태에서는 과일이 멈춘다(v0.5.8/v0.5.9의 PLAYING 게이팅 관례와 동일).
- [ ] **이동 속도(느림)**: 과일 이동은 뱀 tick보다 현저히 느리게 일어난다. 권장 산식 — 과일이 `fruitMoveMs` 간격마다 1칸 이동하며, `fruitMoveMs ≈ stage.tick * 4`(즉 뱀 4틱당 과일 1칸) 또는 고정 `~600ms`/칸. 정확값은 Open Q(dev/오케스트레이터 확정). 어느 쪽이든 "느린 드리프트"로 체감되어야 한다.
- [ ] **그리디 1칸 접근(맨해튼)**: 한 번 이동할 때 과일은 머리와의 `dx = head.x - food.x`, `dy = head.y - food.y` 중 **절댓값이 더 큰 축으로 1칸** 머리에 가까워진다(대각선 이동 없음, 한 번에 1칸). `dx === 0 && dy === 0`(이미 머리 칸)이면 이동하지 않는다(그 tick에 먹힘 처리됨).
  - **동률(`|dx| === |dy|`) 시 우선축**: 기본 x축 우선(또는 y축) — Open Q(dev 재량). 결정값을 코드 주석/Decisions에 남긴다.
- [ ] **보드 경계 클램프**: 과일은 보드 밖으로 나가지 않는다. 이동 결과 좌표가 `[0, cols-1] × [0, rows-1]` 범위를 벗어나면 클램프하거나 그 축 이동을 취소한다. 그리디 접근은 항상 머리 방향이므로 정상적으로는 경계를 넘지 않으나, 안전 클램프를 둔다.
- [ ] **몸통 통과(무해)**: 과일은 뱀 몸통 칸 위로 이동할 수 있다(겹쳐도 무해, 통과). 몸통과 겹친다고 충돌·게임오버가 발생하지 않는다.
- [ ] **머리 닿으면 자동 먹힘(의도된 동작)**: 이동 과일이 머리와 같은 칸에 도달하면(머리가 가만히 있어도) Set D의 먹기 판정으로 먹힌다. 이는 의도된 유인 구조다. 먹힘 판정 타이밍은 Open Q와 무관하게 **뱀 tick의 충돌/먹기 판정 경로**(Set D)에서 격자 단위로 확정된다 — 과일 이동 스텝과 뱀 tick이 별도 타이머라도, 같은 칸이 된 상태가 다음 뱀 tick의 먹기 판정에서 소비된다(또는 과일 이동 직후 같은 칸 즉시 먹기 처리 — dev 재량, 단 점수/성장/bulge 효과는 Set D와 동일해야 함).
- [ ] **렌더 부드러움(권장, dev 재량)**: 과일 이동에 v0.5.8 보간과 유사한 셀-간 선형 보간을 적용해 과일이 칸에서 칸으로 끊겨 보이지 않게 하는 것을 권장한다(필수 아님). 보간 적용 시 PLAYING이 아닐 때는 보간을 끄고 격자 위치에 고정한다.
- [ ] **두 과일 동일 칸 겹침**: 이동 중 두 과일이 같은 칸에 겹치는 것을 허용할지/회피할지는 dev 재량(Open Q). 어느 쪽이든 크래시·먹기 중복 정산이 발생하지 않아야 한다(한 tick에 머리가 닿은 과일 1개만 먹힘).
- [ ] 이동 로직은 새 `setInterval`/`setTimeout` 없이 기존 RAF(`frame`) 루프 내 시간 누적(예: `fruitMoveAccum += dt`)으로 구동하는 것을 권장한다(타이머 추가 회피, v0.5.8/v0.5.9 관례 일치).

### Set F — 다중 과일 렌더

- [ ] 렌더 순서(현 939–942행: background → apple → body → bulges → head)에서 apple 단계가 `foods` 배열을 순회하며 각 과일을 `drawApple`로 그린다.
- [ ] `drawApple`는 **기존 함수를 재사용**한다(새 색·새 폰트·새 에셋 도입 금지). 다중 렌더는 호출을 N번 하는 것뿐이다.
- [ ] 기존 사과 wobble/ambient 모션이 과일별로 적용되어도 시각적으로 어색하지 않다(각 과일 독립). 동기화로 인한 부자연스러움이 있으면 phase 오프셋 등 기존 패턴으로 완화(dev 재량, 신규 토큰 최소화).
- [ ] 이동 과일 보간을 적용하는 경우(Set E), `drawApple`에 전달되는 좌표가 보간된 셀 좌표를 경유한다. PLAYING이 아닐 때는 격자 좌표로 고정된다.

### Set G — 스테이지 전환 / 라이프사이클 회귀

- [ ] 신규 스테이지 4개(St4~7) 추가로 `STAGES.length`가 8이 된다. `advanceStage()`(301행 부근)·`enterStageClear()`·인덱스 경계 처리(`stageIndex >= STAGES.length` → 마지막 스테이지 클램프, 315–317행)가 정상 동작한다.
- [ ] 스테이지 전환 시 `loadStage(idx)`가 v0.5.7.1 패턴대로 `resizeCanvas()`를 재호출(221행)하여 격자/셀 크기를 재계산하고, 그 후 `placeFood()`로 `spawnCount`개 과일을 배치한다.
- [ ] 전체 전환 경로(튜토리얼 → St1 → … → St7)가 끝까지 진행되며, 각 전환에서 `foods`·`bulges`·`snake`·`applesEaten`이 올바르게 리셋된다. St3 클리어 → St4 전환(신규 유한화 경로)과 St6 클리어 → St7 전환(엔드리스 진입)이 특히 검증된다.
- [ ] St7(엔드리스)에서 사과를 `clearAfterApples` 없이 계속 먹어도 전환·크래시 없이 다중·이동 과일 플레이가 지속된다.

### Set H — 회귀 (변경 없음 확인)

- [ ] v0.5.8 렌더 보간(`prevSnake`/`renderT`/`interpGrid`/`cellCenterX/Y`)이 뱀 모션에서 불변이다. 과일 보간을 추가하더라도 뱀 보간 경로는 손대지 않는다.
- [ ] v0.5.9 ambient(tongue flick, yawn)·wiggle 절제·bulge 흐름이 불변이다. 먹기 경로에 추가되는 것은 과일 배열 처리뿐이며, `eatStart`/`tongueFlickAt`/`lastTurnAt`/bulge 시프트의 의미는 유지된다.
- [ ] 충돌 판정 타이밍(`wouldHit(head)` → `gameOver`/`enterBlocked`, 413–416행)이 불변이다. 이동 과일은 충돌과 무관(몸통 통과 무해)하며, 벽·자기 몸통 충돌 로직은 그대로다.

## Decisions

- **(A) food → foods 배열 일반화** — 다중·이동 과일을 깔끔히 지원하려면 단일 객체를 배열로 일반화하는 것이 최소 분기 비용이다. 충돌·렌더·bulge 단일 진입점이 이미 `food.x/y` 한 곳에 모여 있어, 배열 순회로 치환하는 변경 범위가 제한적이다.
- **(B) spawnCount 단계적 증가(St4=5, St5/6/7=10)** — 새 메커닉(다중)을 St4부터 5개로 도입하고 St5 이후 10개로 늘려, 초반(St1~3, 1개)은 학습 곡선을 완만히 유지한다. 오케스트레이터/사용자 확정값.
- **(C) 이동 과일 = `fruitMoves` 스테이지 데이터 플래그** — 이동 기능을 코드 분기가 아닌 데이터 플래그로 구현해, 어느 스테이지에서든 켜고 끌 수 있게 한다. St4~6=false, St7=true(정식).
- **(D) St3 fruitMoves=true는 "검증용 잠정 플래그"** — 사용자 요청("테스트는 St3부터 넣어보고 잘 되면 St7 정식")에 따라, 도달이 쉬운 St3에 이동 과일을 켜 라이브 검증 어포던스를 제공한다. 이는 **잠정**이며, 사용자 평가 후 제거/유지를 별도로 결정한다(향후 패치에서 St3 fruitMoves=false로 되돌릴 수 있음). St7은 정식(엔드리스+다중+이동).
- **(E) 엔드리스 종착역을 St3 → St7로 이전** — 기존 St3가 `clearAfterApples: null`(엔드리스 종착역)이었으나, 스테이지가 St7까지 확장되며 St3는 유한화(clear 5)되고 엔드리스는 마지막 St7로 이전된다. 진행 경로가 St1→…→St7로 끝까지 이어진다.
- **(F) 풀보드 클리어 메커닉 보류** — 원 v0.6 계획(보드를 가득 채워 클리어)은 본 버전에서 구현하지 않는다. 본 슬라이스는 과일 차원 확장(다중·이동)과 스테이지 확장에 집중하고, 풀보드 클리어는 향후 버전으로 미룬다. README 로드맵에 보류를 명시.
- **(G) 신규 필드 기본값으로 하위 호환** — `spawnCount`/`fruitMoves`가 누락된 스테이지는 코드 기본값(`spawnCount=1`, `fruitMoves=false`)으로 해석되어 단일 고정 과일로 폴백한다. 향후 스테이지 추가 시 안전.

## Non-functional Notes

### 페이로드 예산

- 상한 **75KB**. **현재 합계 약 54.9KB**. 리팩터(food→foods)는 대부분 기존 코드를 배열 순회로 바꾸는 치환이라 순증가가 크지 않고, 신규 로직(spawnCount 루프·이동 드리프트·다중 렌더·STAGES 4행 추가)을 더해도 상한까지 여유가 있다.
- 예상 순증가: STAGES 4행 + 신규 2필드(전 행) ≈ 0.6–1.0KB, foods 리팩터 + 이동/respawn 로직 ≈ 1–2KB. 총 < 3KB 예상 → ~58KB 내외, 상한(75KB) 충분.
- **실측 확인 항목**: SCM/QA 단계에서 `game.js + index.html + style.css` 합계 바이트가 75KB 미만임을 확인한다. 빌드툴/미니파이 도입 금지(정적 3파일 유지).

### 성능

- 이동 과일 드리프트·다중 렌더는 기존 RAF(`frame`) 루프 내 산술/순회만 추가한다. 새 타이머 없이 `dt` 누적으로 과일 이동 스텝을 구동(권장).
- 과일 순회는 최대 `spawnCount`(10)개 O(n)이며, 매 tick 먹기 판정·매 프레임 렌더 모두 작은 상수 차수다.
- `placeFood`의 빈 칸 탐색은 보드가 가득 찰수록 비싸질 수 있으므로 시도 상한 또는 빈 칸 목록 방식으로 보호(Set C).

### 정확성 / 논리 불변

- 이동 과일은 **충돌(벽·몸통)과 무관**하다. 몸통 통과는 무해하며, 게임오버/BLOCKED 판정은 뱀 머리 vs 벽/자기 몸통 격자 판정 그대로다(Set H).
- 클리어 판정은 보드 위 과일 수가 아니라 **누적 `applesEaten`** 기준(Set D). 다중 과일이어도 의미 불변.
- 이동·먹기·점수·bulge는 격자 단위로 확정되며, 렌더 보간(과일/뱀)은 화면 좌표 산출에만 관여한다.

### 모바일

- 다중·이동 과일은 입력 경로를 바꾸지 않는다. 터치 회전·캔버스 폴백·하단 버튼 반응 불변.
- 이동 과일이 머리로 다가오므로, 저성능 단말에서 프레임이 떨어져도 과일 이동은 `dt` 누적 기반이라 속도가 프레임레이트에 과도하게 좌우되지 않도록 한다(보간 적용 시 clamp로 오버슈트 방지).
