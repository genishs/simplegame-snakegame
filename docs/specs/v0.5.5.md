# v0.5.5 Spec

## Goal

v0.5.4 모바일 라이브에서 보고된 critical 버그 2건 — 모바일 게임 시작 불가, 튜토리얼 BLOCKED 영구 stuck — 만 패치한다.

## User Stories

- 모바일 플레이어로서, 캔버스를 탭하여 게임을 시작하고 싶다. 그래서 버튼을 찾지 못해도 플레이를 시작할 수 있다.
- 모바일 플레이어로서, 튜토리얼에서 BLOCKED 상태가 되었을 때 같은 방향으로 두 번 입력하여 빠져나오고 싶다. 그래서 모서리에서 영구적으로 멈추는 상황이 발생하지 않는다.

## Acceptance Criteria

### Set A — 캔버스 시작 폴백

- [ ] READY 상태에서 캔버스 탭/클릭 → `auxAction()` 호출 → 게임 시작.
- [ ] PAUSED 상태에서 캔버스 탭/클릭 → `auxAction()` 호출 → 게임 재개.
- [ ] OVER 상태에서 캔버스 탭/클릭 → `auxAction()` 호출 → 재시작.
- [ ] PLAYING 상태에서 캔버스 탭/클릭 → 기존 좌/우 회전 동작 유지 (변경 없음).
- [ ] BLOCKED 상태에서 캔버스 탭/클릭 → 기존 tryUnblock 경유 회전 동작 유지 (변경 없음).
- [ ] STAGE_CLEAR 상태에서 캔버스 탭/클릭 → no-op (`auxAction`이 STAGE_CLEAR에서 inert이므로 아무 일도 일어나지 않음).
- [ ] canvas `pointerdown` 핸들러 진입부에서 `state === STATE.READY`, `STATE.PAUSED`, `STATE.OVER` 중 하나이면 `auxAction()`을 호출하고 즉시 return한다. 회전 로직은 그 아래(PLAYING/BLOCKED 전용)에 위치한다.
- [ ] 모바일 하단 버튼(좌 회전/aux/우 회전) 자체의 `pointerdown` 핸들러는 변경하지 않는다.

### Set B — 매체쿼리 완화

- [ ] 모바일 분기 매체쿼리가 `@media (max-aspect-ratio: 1/1)` 단독으로 변경된다.
- [ ] 기존 `(hover: none) and (pointer: coarse)` 조건이 제거된다.
- [ ] 데스크탑 브라우저에서 창을 세로로 좁혀 세로 길이 > 가로 길이가 되면 하단 컨트롤 버튼이 노출된다. (의도적 — 모바일 모드 시뮬레이션 및 회귀 안전망)
- [ ] `@media (max-aspect-ratio: 1/1)` 블록 내부의 `:root`, `.mobile-controls`, `.m-btn`, `.m-rotate`, `.m-aux`, `.hint` 규칙은 변경하지 않는다.

### Set C — BLOCKED 회복 누적

- [ ] BLOCKED 상태에서 좌/우 회전 입력 시 `nextDir`은 회전 결과로 항상 갱신된다 (isSafeDir 결과에 관계없이).
- [ ] `isSafeDir(nextDir.x, nextDir.y)`가 true일 때만 `dir = nextDir`, `state = STATE.PLAYING`, `tickAccum = 0`, `hideOverlay()`, `updateAuxButton()`이 실행된다.
- [ ] `isSafeDir`이 false이면 BLOCKED 상태 유지, `dir` 변경 없음, 오버레이 텍스트 변경 없음.
- [ ] BLOCKED에서 같은 키 두 번(90° + 90° = 180°) 입력 시 `nextDir`이 두 번 누적 갱신되어, 두 번째 입력 후 `isSafeDir`이 true이면 PLAYING으로 복귀한다.
- [ ] BLOCKED에서 좌→우 또는 우→좌(90° + 90° = 원상복귀) 입력 시 `nextDir`이 원래 `dir`로 돌아오지만, 그 방향도 안전하지 않으면 BLOCKED 유지된다.
- [ ] BLOCKED 진입 직후 첫 회전이 unsafe → BLOCKED 유지, `nextDir` 갱신, 오버레이 텍스트 변경 없음 (카피 변경 없음).
- [ ] BLOCKED 상태에서 회전 입력 시 `dismissHint()` 호출은 기존 `applyTurn` 동작 그대로 유지된다 (변경 없음).

### Set D — 회귀 (변경 없음 확인)

- [ ] PLAYING 상태에서 좌/우 회전 입력 동작은 v0.5.4와 동일하다.
- [ ] BLOCKED 진입 조건(tick 충돌 처리)은 v0.5.4와 동일하다.
- [ ] 모바일 하단 버튼(좌 회전/aux/우 회전)의 동작은 v0.5.4와 동일하다. 캔버스 폴백이 더해질 뿐 버튼 핸들러 자체는 변경되지 않는다.
- [ ] Space 키의 start/pause/restart 동작은 v0.5.4와 동일하다.
- [ ] Space 키가 PAUSED에서 재개(resume)를 처리하는 것과 동일하게, 캔버스 폴백도 PAUSED에서 `auxAction()`을 호출하여 재개한다.
- [ ] 총 페이로드 50KB 이내 유지 (현재 29.2KB, 이번 변경 추가량 미미).

### Set E — 메타파일

- [ ] `VERSION` 파일이 `0.5.5`로 갱신된다.
- [ ] `index.html` 버전 표기가 `v0.5.5`로 갱신된다.
- [ ] `HISTORY.md` 최상단에 v0.5.5 항목이 추가된다. 두 버그 fix 설명 및 결정 근거(회전 모델 일관성 유지, 캔버스 폴백 일관성 보너스) 포함.
- [ ] `README.md` Roadmap 표에 v0.5.5 행이 추가된다.

## Open Questions

- (해소됨) BLOCKED 누적 입력 허용 여부: 허용. `nextDir`은 항상 갱신, `isSafeDir` 통과 시에만 PLAYING 복귀.
- (해소됨) 4방향 임시 허용 여부: 거부. 회전 모델 일관성 유지.
- (해소됨) BLOCKED에서 unsafe 회전 시 오버레이 텍스트 변경 여부: 변경 없음. 카피 변경 없음.
- (해소됨) BLOCKED에서 회전 시 `dismissHint()` 호출 여부: 기존 `applyTurn` 경유이므로 변경 없이 유지.
- (해소됨) 캔버스 폴백이 PAUSED를 다루는 것과 Space 키의 PAUSED 재개 일관성: Space는 `auxAction()` 호출, 캔버스 폴백도 `auxAction()` 호출 — 동일 경로로 일관성 유지.

## Non-functional Notes

### 페이로드

- 이번 변경은 JS 분기 추가 (~5줄) + CSS 조건 문자열 단축 수준. 순증가량 < 0.1KB. 현재 29.2KB → 예상 ~29.3KB, 50KB 상한 이내.

### 성능

- 추가 연산 없음. canvas `pointerdown` 핸들러 진입부 분기 1회 추가 (이벤트당 조건 비교 1회, 미미).

### 접근성

- 캔버스 폴백 추가로 터치 대상 영역이 확대됨. 기존 버튼 44px 최소치 기준은 변경 없음.
- 스크린리더 접근성: `<button>` + `aria-label` 구조 변경 없음.

### 모바일 고려사항

- 매체쿼리 완화(`(hover: none) and (pointer: coarse)` 제거)로 일부 데스크탑에서도 세로 창이면 버튼이 노출됨. 이는 의도된 동작이며 회귀 안전망으로도 기능한다.
- `touch-action: manipulation` 캔버스/버튼 설정은 변경 없음.

## Decisions

- **(A) 캔버스 폴백으로 auxAction 호출** — v0.5.4에서 캔버스 `pointerdown`은 READY/PAUSED/OVER 상태에서 회전만 큐잉하고 게임 시작을 하지 않았다. 이로 인해 모바일에서 버튼 미인식 시 게임 시작이 불가능했다. 캔버스 탭을 aux 버튼과 동일한 폴백으로 처리하여 일관성을 확보한다.
- **(B) 매체쿼리에서 hover/pointer 조건 제거** — `(hover: none) and (pointer: coarse)`는 일부 모바일 기기에서 인식되지 않아 버튼이 노출되지 않았다. `(max-aspect-ratio: 1/1)` 단독 조건으로 단순화하여 세로 화면이면 버튼을 노출한다.
- **(C) BLOCKED에서 nextDir 항상 갱신** — 기존 `tryUnblock`은 `isSafeDir` 실패 시 즉시 return하여 `nextDir`이 갱신되지 않았다. 이로 인해 같은 키 두 번으로 180° 복귀가 불가능했다. `nextDir`을 분리하여 항상 갱신하고, PLAYING 복귀 조건만 `isSafeDir`로 게이팅한다.
- **(D) 4방향 임시 허용 거부** — 회전 모델(좌/우 상대 회전)의 일관성을 유지한다. BLOCKED 누적 입력(C)으로 동일한 탈출 경로를 제공하면서 모델 변경 없이 해결한다.
